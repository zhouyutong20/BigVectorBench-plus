# U1 HNSWlib 谓词执行成本实验结果

## 1. 实验配置

实验在 U1 `artificial-udf-12` 上完成，包含 991,000 条 256 维底库向量、10,000 条查询、`k=100` 和 12% 的过滤通过率。索引固定为 HNSWlib `M=64`、`efConstruction=400`，查询使用 28 个外层 worker，每个 HNSWlib 查询使用 1 个内部线程。

比较两条保持相同过滤回调接口的路径：

- `precomputed`：回调直接读取由同一 32 轮 SplitMix64 谓词生成的预计算标签；
- `online`：回调在线执行原始 32 轮 SplitMix64 谓词。

搜索预算为 `ef={200,400,800}`。每个点先进行两轮、每轮 1,000 条查询预热，再进行 5 次完整 10,000 条查询的未插桩性能测量；计数和谓词计时另行执行，不与 QPS 测量相加。

## 4. 主要观察

### 4.1 搜索路径和检索质量保持一致

在相同 `ef` 下，预计算和在线路径的 Recall、平均返回数量、谓词调用数、距离计算数、邻接扫描数和 hops 均一致。例如，在 `ef=800` 时，两条路径都执行约 12,303 次谓词判断、87,488 次距离计算和 357,336 次邻接项扫描，并达到 Recall@100=0.999971。这说明两条路径的差异没有来自不同的搜索预算或不同的候选访问路径。

### 4.2 搜索预算增加会放大谓词执行次数

从 `ef=200` 增至 `ef=800` 时，谓词调用数从 3,626.16 增至 12,303.42 次/查询，约增加 3.39 倍；邻接扫描数从 90,101.85 增至 357,335.82 次/查询，约增加 3.97 倍。搜索预算提高带来了更高的过滤检查工作量，同时 Recall 从 0.998906 提升至 0.999971。

### 4.3 在线谓词计算造成稳定的端到端性能损失

在线 32 轮路径的累计谓词函数体时间约为预计算路径的 26.2--26.6 倍。对应的未插桩端到端结果显示，在线路径的平均延迟约为预计算路径的 4.31--4.47 倍，p95 延迟约为 5.62--5.89 倍，QPS 降至预计算路径的约 22%--23%。

例如，在 `ef=400` 时，预计算路径达到 24.823 QPS，而在线路径为 5.547 QPS；两者 Recall 均为 0.999826，平均谓词调用数均为 6,658.81 次/查询。该结果表明，在搜索路径和检索质量相同的情况下，在线执行高成本谓词会显著降低完整查询吞吐并增加尾延迟。

需要注意，累计谓词时间来自独立的计时插桩 pass，不能与未插桩端到端延迟直接相加。它用于刻画回调函数体的相对成本；实际端到端差异还包含 Python 回调进入、线程调度和 GIL 竞争等执行开销。

## 5. 可用于论文的简短结论

在 U1 上，我们使用同一 HNSWlib 索引、过滤集合、查询和回调接口，仅将回调体从预计算标签读取替换为原始 32 轮 SplitMix64 计算。两条路径在每个搜索预算下产生完全一致的谓词调用数、距离计算数、邻接扫描数和 Recall，因此该对照隔离了谓词执行成本。随着 `ef` 从 200 增至 800，谓词调用数从 3,626 增至 12,303 次/查询，Recall 从 0.998906 提升至 0.999971；在线谓词的累计函数体时间约为预计算路径的 26 倍，并使 QPS 降低约 4.3--4.5 倍、p95 延迟增加约 5.6--5.9 倍。结果说明，过滤谓词的执行成本会随搜索预算放大，并直接传递到完整查询的吞吐和尾延迟中，而不是改变 ANN 搜索路径或检索质量。
